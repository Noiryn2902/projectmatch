# ProjectMatch — working rules

Built for PromptWars under a 3 hour clock. These constraints are deliberate; keep them.

## Hard constraints

- **No database, no auth, no persistence.** All data is seeded JSON in `lib/data/`, generated by `scripts/seed.mjs`. State lives in React only, so a refresh returns to a working default rather than an empty form.
- **One API route.** Everything AI goes through `app/api/ai/route.ts` with an `action` discriminator. Do not add a second route.
- **Structured JSON, never prose.** Gemini calls use `responseSchema`. Anything the model returns is validated and resolved against the skill vocabulary before it reaches the engine.
- **Every AI call has a deterministic fallback** in `lib/ai/fallback.ts`. The app must work fully with the network unplugged.
- **380px safe.** Check every change at 380px width before calling it done.
- **Loading and error states from the start**, not bolted on later.

## Architecture

`lib/engine/` is pure TypeScript. No React, no `fetch`, no async. That is what lets the whole thing be verified from a terminal:

```bash
npx tsx scripts/test-engine.ts
```

Run that after any change to scoring. It prints the auto-filled team, the coverage, and the core claim: a duplicate skill adds ~0% while the missing role adds real percentage points. If that inverts, the product is broken regardless of what the UI looks like.

## The one rule about AI

**Gemini never picks the team.** It reads the brief into structured requirements, and it writes the sentence explaining a pick. The choosing is deterministic code in `lib/engine/`, so the same brief always yields the same roster. If you find yourself asking the model to rank or choose people, stop.

## Scoring

Weights live in `scoreCandidate` in `lib/engine/score.ts`. Two invariants:

- `gapFill` carries the most weight, or complementarity stops driving the ranking.
- `fitsSeat` must stay meaningful, or the optimiser parks a designer in the backend chair. It also has a hard floor in `improve()`.

Requirement satisfaction is capped by skill similarity, so an adjacent skill can never read as fully covering a requirement. Removing that cap sends coverage to a meaningless 100%.

## Anything user facing

No em dashes. No stock filler. Sentence case. Say the number, not "significantly improved".
